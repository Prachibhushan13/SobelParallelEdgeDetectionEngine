1. Mathematical Foundation of the Sobel Operator

The Sobel operator performs a 2D spatial gradient measurement on an image, emphasizing regions of high spatial frequency that correspond to edges.

Horizontal Gradient Kernel (Gx):
[-1 0 1]
[-2 0 2]
[-1 0 1]
Detects vertical edges (horizontal intensity changes)

Vertical Gradient Kernel (Gy):
[-1 -2 -1]
[ 0 0 0]
[ 1 2 1]
Detects horizontal edges (vertical intensity changes)

Gradient Magnitude:
G(x, y) = √( Gx² + Gy² )
Clamped to 8-bit unsigned integer range: I_out(x, y) = min(255, G(x, y))

2. Why Sobel Edge Detection is Embarrassingly Parallel

The Sobel operator is a stencil convolution computation. To calculate output pixel I_out(x, y), the algorithm only reads the 3×3 neighborhood in the input image I_in.

  • Read-Only Input: The source image memory is never modified during convolution.
  • Disjoint Writes: Each parallel thread writes strictly to its assigned rows/pixels in the separate output buffer.
  • No Race Conditions: Zero thread synchronization or atomic locks are needed during convolution!
  • Cache Line Alignment: Row-wise partitioning (OpenMP #pragma omp parallel for schedule(static)) ensures each thread processes contiguous bytes, preventing false sharing across hardware cache lines.

3. Performance Metrics and Amdahl's Law

Speedup Factor:
S(p) = T_sequential / T_parallel(p)

Parallel Efficiency:
E(p) = (S(p) / p) × 100%

Amdahl's Law:
S(p) = 1 / [ (1 - f) + (f / p) ]
where f is the parallel fraction of the program (stencil convolution ≈ 98-99%), and 1 - f is the sequential portion (setup, thread dispatch).
